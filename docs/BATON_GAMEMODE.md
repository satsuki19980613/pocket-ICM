## 1. 何をしたか（一言で）

クラブマッチ専用だった計算を、**ゲームモードごとのプライズ・開始スタックで解けるように一般化**した。
UI は 2 段セグメント（上段＝クラブ / ランク / レジェンド、下段＝ランクは STAGE、レジェンドは指標）。

対応モードは 7 つ: `club` / `rank-3` / `rank-4` / `rank-5` / `legend-avg` / `legend-season` / `legend-base`。

## 2. 設計の軸（ここを覆すと全部やり直しになる）

1. **ブラインドは全モード共通**（SB0.5/BB1・ante 0.25bb 全員払い・同じ公式レベル表）。
   モード差は上昇間隔と開始スタックだけで、**bb 単位の局面には現れない**。だから事前計算表の
   適用条件（blinds/ante 一致）はどのモードでも満たす。ブラインド周りの改修はゼロ。
2. **変わるのは payout と総チップだけ。** payout は `payoutsForPlayers(n, mode)` 一点を通す。
3. **総チップ = 開始人数 × 開始スタック**。1 定数で持たない（STAGE Ⅰ が 4 人卓のため）。
4. **総チップからモードを自動判定してはいけない。** `rank-4`=`club`=90,000、`rank-5`=`legend-*`=120,000 と
   衝突する。判定は UI の選択のみ。総チップは「選択と食い違ったときの警告」にだけ使う（さつき決定）。
5. **事前計算表はクラブ専用**（クラブの payout を焼き込んで生成した）。他モードは厳密求解に回す。
   表の追加生成は**見送り決定**（3 指標ぶんで約 40MB＋生成数時間に対し、縮むのは非同期ジョブの数秒）。
6. **HU は全モードで戦略が同じ**（2 着払いは必ずアフィン等価）。HU 表は流用。検証で push 123 手・
   call 85 手が 7 モード完全一致することを実測済み。
7. **表示 pt はクラブ尺度に正規化**（`toDto` で 1 回だけ `ptDisplayScale` を掛ける）。記録一覧の
   EV ロスを横比較できるようにするため。戦略・収束判定は換算前の値で行う。

## 4. 途中で見つけて直した不具合（レビュー時の重点）

1. **レジェンドの 6 人 payout はゼロサム**（総和ちょうど 0）。早期終了しきい値が `Σpayouts × k` で
   0 になり、**永久に早期終了しない**（6 人が上限 3000 反復に張り付いた）。総和が使えないときは
   **振れ幅（max−min）**に切り替えて解決。club は総和>0 なので挙動不変。
2. **未読 1 席の復元がモード依存なのに無警告だった**（同一フレームで club 10.9bb / legend 42.15bb と
   約 4 倍差）。しかも未読席が差分を吸収する構造上、**総チップ照合では原理的に検出できない**。
   → 「モード依存の復元をした」印を返し、確認画面で注意を出す形に。
3. **hero が深い（>25bb）警告が club でしか出なかった。** `pfCoverage` がモード判定を先に置いていたため、
   同じ盤面でクラブは「対象外」、ランクは黙って数値を返す非対称。判定順を入れ替えて解消。
4. **HU の収束しきい値が絶対値固定**で、レジェンドだけ 12.5 倍厳しく反復上限に張り付いていた。
   payout の振れ幅比でスケールするよう変更（club は比 1 で不変）。
5. **bb 表示が `formatBbDisplay` を通っていなかった**（通っていたのはポットだけ）。実機に存在しない
   桁（42.15bb）が出ていた。4 か所を修正＋ソースを見張るテストを追加。
6. **未読 2 席以上のとき、修正を促していなかった**。補正はもともとしていない（一意に解けない）が、
   仮値 0bb にチェック印が付くだけで見過ごせた。確認画面に赤い警告を出すようにした（さつき指示）。

## 6. レビューで見てほしい観点

- **`ptDisplayScale` の設計**: フル 6 人分の振れ幅で正規化している。局面の残人数が減って payout の
  スライスが偶然アフィン同値になっても表示値は一致しない（意図どおりだが、クロスモードの厳密比較には
  使えない）。この割り切りでよいか。
- **未読 1 席の復元を、そもそも続けるか。** 警告は出すようにしたが、モード取り違え時に静かに
  4 倍ずれる性質は残る。「2 席以上と同じく復元せず修正を促す」に倒す選択肢もある。
- **ランクマッチのプライズを載せたままでよいか**（公式に記載が無く、攻略 Wiki 頼み。§7 参照）。
- 3 ゲーム化で `GameSel`（系統ごとに最後の選択を保持）がやや込み入った。もっと素直にできないか。

## 9. 調べ物の教訓（次に同じ穴に落ちないため）

- 公式の**古いお知らせは消える**。クラブマッチ season1〜22、シーズンマッチ season1〜31 は 404。
  「一度も変わっていない」証明は取れないので、**想定と違ってもエラーにせず警告に留める**設計にしてある。
- **攻略サイトの定型文に注意**。zero-poker の STAGE 別ページは開始スタックと人数の出典としては有効だが、
  順位別ポイントは stage2/3/4 に一字一句同じ定型文があるだけで**クロスチェックに使えない**。
- **検索エンジンの要約は年を間違える**（2021 年の記事を 2024/2026 と要約した実例あり）。重要な数値は
  必ずページ本文を取得して日付表記を確認すること。
- Python でファイルを書き換えると **Windows では改行が CRLF に変わって差分が全行に膨らむ**。
  書き込みは `newline=''` を付けるか、元ファイルの改行を確認してから。
