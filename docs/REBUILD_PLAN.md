## 1. アーキテクチャ

### 1.1 全体構成（ゼロ課金を最優先）

| レイヤ | 採用 | 課金リスク |
|---|---|---|
| フロント配信 | **Cloudflare Workers（現状維持）** 静的アセット | カード未登録＝課金不能（現状どおり） |
| 認証 | **Supabase Auth** | 下記のとおり課金不能 |
| DB（スレッド・記録メタ・公開設定） | **Supabase Postgres + RLS** | 同上 |
| 画像（プロフ・スレッド添付） | **Supabase Storage** | 同上 |
| ソルバー | **端末内 Web Worker（現状維持）＋事前計算テーブル/NN** | サーバ計算しない＝ゼロ |

ソルバーは**引き続き完全にクライアント側**で動く（HU/3/4人=テーブル, 5-6人=NN, いずれも端末内）。
サーバは「アカウントと共有データ（スレッド・公開記録・画像）」だけを担う。**求解はサーバに投げない**＝計算コストによる課金は原理的に発生しない。

### 1.2 ゼロ課金の保証（絶対条件の担保）

- **Supabase 無料枠はクレジットカード登録が不要**。カードが無い＝**物理的に課金され得ない**。
  無料枠超過時の挙動は「課金」ではなく「サービス制限（通知後）」。（出典: Supabase Billing FAQ, 2026）
- 無料枠: DB 500MB / 認証 5万MAU / ストレージ1GB / 帯域5GB/月 / API 無制限 / プロジェクト2つまで。
  **利用者は最大25人**なので全項目に対して桁違いの余裕（実使用は1%未満の見込み）。
- **Firebase は不採用**: 2026/2/3 以降 Cloud Storage が Blaze（＝**カード紐付け必須**）に移行。
  カードが乗る時点で絶対条件に反する。
- **Cloudflare も現状カード未登録**で運用中（課金不能）。フロントは現状維持。
- 運用ルール: **どのサービスにも支払い方法を登録しない**。これを破らない限り課金は起きない。

### 1.3 Supabase 無料プロジェクトの「7日ポーズ」対策

無料プロジェクトは7日間無操作でポーズ（次回アクセス時に数秒のコールドスタート）。
- クラブは活動中のため通常は発生しない見込み。
- 保険として **GitHub Actions の無料 cron（週1回の軽い ping）** で warm を維持（GitHub Actions も課金なし枠内）。

### 1.4 セキュリティ方針（「しっかりと」への回答）

- 認証は **自作せず Supabase Auth**（実績あるパスワードハッシュ・セッション管理）を使う。
- DB は **Row Level Security (RLS)** で「自分の記録は自分だけ編集/削除」「公開記録は全員閲覧」を DB レベルで強制。
- **招待キー検証と25アカウント上限は必ずサーバ側**（Supabase Edge Function）で判定（クライアント判定は不可＝改竄可能なため）。
- 画像アップロードは Storage ポリシーで本人のみ書込み可・サイズ/MIME 制限。

## 2. 招待制アカウント（新規）

- **サインアップ**: 表示名・ユーザー名（@handle）・パスワード＋**招待キー**を入力。
- **招待キー**: さつきが招待者に口頭/DMで渡す**単一の共有キー**。Edge Function がキー一致を検証。
- **上限25アカウント**: サインアップ時に Edge Function が現アカウント数を数え、**25未満のときだけ**作成を許可。25到達で新規作成を締切（「現在満席です」表示）。
- ログイン/ログアウト。パスワード変更（設定画面）。
- **プロフィール画像**（設定画面で選択・Supabase Storage）。
- **アカウント削除**（設定画面。自分の記録・スレッド・画像も連鎖削除）。

## 3. 画面仕様

### 3.1 ホーム（新規・最重要の SNS 面）

- **フィード**: 公開された計算結果が**スレッド**として並ぶ（新しい順）。各投稿＝投稿者・コメント・結果カード（手札/判定/bb/PU%/EV）・返信数・♡。
- **公開**: 計算結果画面から「ホームで公開」＋コメントで投稿。**公開は任意**（既定は非公開／自動保存のみ）。
- **スレッド**: タップで詳細。任意のアカウントが**自由に返信**（**画像添付可**）。
- **自分の投稿コメントの編集**（スレッド/フィードから）。
- **他人のプロフ画像タップ → その人が公開した計算結果一覧**（読み取り専用ビュー）。
- **自分のプロフ画像タップ → 記録タブへ遷移**。

### 3.2 ICM 計算（刷新）

- **写真選択ボタンをトップに配置**、その下に「読み取れる条件」チェックリスト（モック準拠）。
  画像から ICM を出すのがメイン体験のため写真起点を最上位にする。
- **手入力はサブ**: 「手入力する」ボタン → **手入力モーダル**（現在の手入力フォームをモーダル化）。
- 写真選択後 → **条件確認/修正画面**（読み取り内容の表示・各項目「修正」・低信頼強調）。
- 対象外/読取失敗 → **エラー画面**（欠けている項目・「別の写真」/「読めた分を手入力」）。

### 3.3 計算結果（刷新＝モックが正）

- **判定 ヒーロー**: PUSH/FOLD 大表示＋手札・ポジション・スタック・残り人数・EV。
- **Action tree（最重要）**: **全ポジションを常時1行ずつ表示**し、各行にインラインでアクション切替
  （FOLD / PU or CA or OC。前段の状態で自動的に種別が変わる）。**すべてのポジションのすべての条件を指定でき**、
  選んだノードのレンジ表が連動する。全員フォールドで BB 手番の枝は "no decision" ロック。
  （＝ソルバーは既に全ノード[2^N−2]を返すのでデータは揃っている。UI をモック準拠に作り直す。）
- **BB のオールインへの受けレンジ**もこの tree の CA/OC ノードとして表示（ソルバー既算出）。
  ※スクショから「誰がオールインか」を読む OCR は既存の allin 検出を流用（必要なら追加較正）。
- **Frequency bar / 13×13 レンジ表（自分の手ハイライト）/ レンジ記法 / ICM equity（EQPre/EQPost/EQDiff）**。
- **自動保存**。**公開は任意**（公開トグル＋コメント）。削除可。

### 3.4 記録タブ

- 過去の計算結果＋公開した結果（スレッド含む）を一覧。集計（場面数・EV loss 累計）。
- 各記録の**削除**。公開/非公開タグ表示。

### 3.5 設定（アカウント）

- プロフィール画像の選択・表示名/ユーザー名/パスワード変更。
- 公開のしかた（既定公開の ON/OFF 等）。
- **アカウント削除**。ログアウト。

### 3.6 トレーニング（Drill）＝一旦伏せる

- タブは残してよいが **"Coming Soon"** 表示（未完成のため非公開）。既存 Drill 実装はコード上は温存。

## 7. リスクと対処

| リスク | 対処 |
|---|---|
| **課金発生（絶対NG）** | どのサービスにもカードを登録しない。Supabase無料枠（カード不要=課金不能）。Firebase不採用。 |
| プライバシー（共有スクショに他人の実名/スタック） | 招待制25人の閉じたクラブに限定。公開は任意・既定オフ。README/UIで注意喚起。将来: 名前マスク。 |
| RTA 懸念（規約） | 従来どおり**プレイ後のスクショのみ**・RTAなし。SNSは「復習の共有」で規約線を越えない。 |
| Supabase 7日ポーズ | GitHub Actions 無料 cron で warm 維持。最悪コールドスタート数秒許容。 |
| NN が合格ゲート未達 | 点追加/モデル拡大/境界重み付けで反復。テーブル路（2-4人）は影響なし。手入力は常に可。 |
| スコープ肥大 | マイルストーンで区切り、各Mを完了基準で締める。Drillは伏せて負荷を下げる。 |
