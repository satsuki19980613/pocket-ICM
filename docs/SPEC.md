## 0. プロダクト概要

- 招待制の**閉じたクラブ内 ICM 学習ツール兼 SNS**（利用者は最大25人）。
- コア体験＝**トーナメントのスクショ → OCR → push/fold の最適解を即時表示**。復習を仲間と共有できる。
- ソルバーは**完全に端末内**で動く（HU/3人/4人＝事前計算テーブル、5-6人＝NN蒸留）。
  サーバは「アカウントと共有データ（スレッド・公開記録・画像）」のみを担う。
- **絶対条件: いかなる場合も課金が発生しない**（§7）。

## 1. 用語

| 用語 | 意味 |
|---|---|
| スポット | 1つのハンド状況（人数・スタック・自分の手・ポジション等） |
| push / fold | オールイン or フォールドの二択（AOF: All-in or Fold）。※「押し引き」表記は使わない |
| ノード | Action tree 上の1つの決定点（各ポジション×各前段状態） |
| PU / CA / OC | Push / Call / Over-call（前段状態で種別が変わる） |
| 公開 | 計算結果をホームのスレッドに出すこと（既定オフ） |
| 招待キー | アカウント作成に必要な**1回限りの使い捨てコード**（§3） |

## 2. アカウント / 認証

- **サインアップ**: 表示名・ユーザー名（@handle）・パスワード＋**招待キー**を入力。
  - 招待キーが有効で、かつ登録人数が上限未満のときだけ作成できる（判定は必ずサーバ側）。
- **ログイン / ログアウト**。パスワード変更（設定画面）。
- **プロフィール画像**（設定画面で選択）。
- **アカウント削除**（設定画面。自分の記録・スレッド・コメント・画像も連鎖削除）。
- 対応画面: `auth`（ログイン / 作成）, `profile`（設定）。

## 3. 招待キー（★今回の確定仕様：1人ずつ・使い捨て）

さつきが**1人ずつ**招待する。招待のたびに**毎回異なるキーを1つ発行**し、相手に渡す。

### 3.1 キーの性質（シンプル＆安全）
- **1回限り**: 1つのキーで作れるアカウントは1つだけ。使われた瞬間に無効化。
- **推測不可**: 暗号学的乱数で生成。曖昧文字（0/O/1/I/l）を除いた英数字。
  - 形式: `POCKET-XXXX-XXXX`（読みやすい区切り。LINE等で送りやすい）。将来、桁数は容易に増やせる。
- **有効期限**: 既定 **7日**（未使用のまま期限切れ→自動失効）。期限は管理画面で変更可。
- **保存はハッシュのみ**: DB には生キーを保存せず**ハッシュ**を保存。DB が漏れてもキーは使えない。
  - 生キーは**発行時に一度だけ**画面表示（コピー可）。以後は本人も見られない（再発行で対応）。
- **状態**: 未使用 / 使用済み / 取消 / 期限切れ。

### 3.2 サインアップ時のサーバ側検証（Edge Function）
1. キーのハッシュが「未使用・未失効・未取消」で存在するか。
2. 現アカウント数 < 上限か。
3. 両方満たせばアカウント作成 → キーを「使用済み（used_by/used_at）」に更新（原子的）。
4. どれか満たさなければ拒否（理由別メッセージ: 無効キー / 期限切れ / 満席）。

## 4. 管理画面（★新規・さつき専用）

さつきのアカウントだけがアクセスできる画面。画面 ID: `admin`（モックに新設）。

### 4.1 入り方（安全策）
- 新しいパスワードは作らない。**さつきの通常アカウントに「管理者」フラグ（`is_admin`）を1つ付与**する方式。
- ログイン中に管理者フラグがあるときだけ管理画面が出る。他ユーザーには存在ごと見えない。
- 管理者フラグの付与は**初期設定時に1回だけ**（DB直・開発者作業）。アプリ上に昇格機能は作らない。

### 4.2 できること
- **登録状況**: 現在の登録人数 `X / 上限`。
- **アカウント上限の変更**: 数値入力（初期値25）。サーバ側で強制。
- **招待キーの発行**: ボタン1つ → 使い捨てキーを生成し**一度だけ表示**（コピー可）。
- **招待キー一覧**: マスク表示のキー・状態・使った人・発行日・有効期限。
- **未使用キーの取消**（revoke）。
- （任意）**アカウントの停止/削除**は将来拡張（v2 では最小限）。

### 4.3 サーバ側の保証
- 上限変更・キー発行/取消は**管理者フラグを持つ本人のみ**（RLS＋Edge Function で二重に強制）。
- クライアント判定に依存しない（改竄不能）。

## 5. 画面仕様（モック準拠）

各項目末尾の `code` はモックの画面 ID（`data-go`）。

### 5.1 ホーム `home` / スレッド `thread` / 他人の公開 `userpub`（SNS 面）
- **フィード**: 公開された計算結果がスレッドとして新しい順に並ぶ。各投稿＝投稿者・コメント・
  結果カード（手札/判定/bb/PU%/EV）・返信数・♡。
- **公開**: 計算結果画面から「ホームで公開」＋コメントで投稿。**既定は非公開**（自動保存のみ）。
- **スレッド詳細** `thread`: 任意アカウントが自由に返信（**画像添付可**）。
- **自分の投稿コメントの編集**（フィード/スレッドから）。
- **他人のプロフ画像タップ → その人が公開した結果一覧** `userpub`（読み取り専用）。
- **自分のプロフ画像タップ → 記録タブ** `records`。

### 5.2 ICM 計算入力 `icm` → `confirm` / `error`
- **写真選択ボタンを最上位**に配置、その下に「読み取れる条件」チェックリスト（モック準拠）。
- **手入力はサブ**: 「手入力する」ボタン → **手入力モーダル**（現行フォームをモーダル化）。
- 写真選択後 → **条件確認/修正** `confirm`（読み取り内容表示・各項目「修正」・低信頼強調）。
- 対象外/読取失敗 → **エラー** `error`（欠け項目・「別の写真」/「読めた分を手入力」）。
- **取り込み条件＝スタックが BB 表示のスクショのみ（2026-09-07 追加, さつき決定）**: スタックが
  BB 表示（例: `20.2 BB`）の画面だけ取り込める。**チップ総額表示（例: `19,453`）は取り込み不可**＝
  `error` で「BB表示のスクショを使ってください」と案内し手入力へ誘導。判定は表示モード検出
  （OCR `detectDisplayMode`）で行い、BB 以外は `prefillFromScreenshot` が `ok:false`＋issue で弾く。
  ※チップ→BB 正規化の不確実性を除き、当面 OCR を BB 表示に一本化して精度を確保するための制限。

### 5.3 計算結果 `result`（★モックが正）
- **判定ヒーロー**: PUSH/FOLD 大表示＋手札・ポジション・スタック・残り人数・EV。
- **Action tree（最重要）**: 全ポジションを常時1行ずつ表示。各行にインラインでアクション切替
  （FOLD / PU or CA or OC。前段状態で種別が自動で変わる）。**全ポジションの全条件を指定でき**、
  選んだノードのレンジ表が連動。全員フォールドで BB 手番の枝は "no decision" ロック。
- **BB のオールインへの受けレンジ**も tree の CA/OC ノードとして表示（ソルバー既算出）。
- **Frequency bar / 13×13 レンジ表（自分の手ハイライト）/ レンジ記法 / ICM equity（EQPre/EQPost/EQDiff）**。
- **自動保存**。**公開は任意**（公開トグル＋コメント）。削除可。

### 5.4 記録タブ `records`
- 過去の計算結果＋公開した結果（スレッド含む）を一覧。集計（場面数・EV loss 累計）。
- 各記録の**削除**。公開/非公開タグ表示。

### 5.5 設定 `profile`
- プロフィール画像の選択・表示名/ユーザー名/パスワード変更。
- 公開のしかた（既定公開の ON/OFF 等）。
- **アカウント削除**。ログアウト。
- （管理者のみ）**管理画面へ**の導線。

### 5.6 トレーニング（Drill）`drill` = 一旦伏せる
- タブは残し **"Coming Soon"** 表示。既存 Drill 実装はコード上は温存。

## 7. 絶対条件：ゼロ課金

- バックエンドは **Supabase 無料枠**（Auth / Postgres+RLS / Storage）。
  **クレジットカード未登録＝物理的に課金され得ない**。無料枠超過は「課金」ではなく「制限（通知後）」。
- **どのサービスにも支払い方法を登録しない**（Supabase / Cloudflare とも）。これを破らない限り課金は起きない。
- **Firebase 不採用**（2026/2/3 以降 Storage が Blaze＝カード必須のため）。
- フロント配信は **Cloudflare Workers（現状維持・カード未登録）**。
- 無料枠目安: DB 500MB / 認証 5万MAU / ストレージ1GB / 帯域5GB/月。利用25人では桁違いに余裕。
- Supabase の7日ポーズ対策: GitHub Actions 無料 cron で週1 warm ping。

## 8. セキュリティ方針

- 認証は**自作せず Supabase Auth**（実績あるハッシュ・セッション管理）。
- **Row Level Security (RLS)** で「自分の記録は自分だけ編集/削除」「公開記録は全員閲覧」を DB レベルで強制。
- **招待キー検証・上限・管理操作は必ずサーバ側**（Edge Function＋RLS）。クライアント判定に依存しない。
- 画像は Storage ポリシーで本人のみ書込み・サイズ/MIME 制限。
- 招待キーは**ハッシュ保存**・使い捨て・期限付き（§3）。

## 9. データモデル（機能面・確定は実装計画 M1 で詳細化）

- `profiles`: user_id, handle, display_name, avatar_url, **is_admin**, created_at
- `app_config`: max_accounts（既定25）ほか運用値（単一行）
- `invite_codes`: id, **code_hash**, created_by, created_at, expires_at, status, used_by, used_at
- `results`: id, owner, スポット条件・解（メタ）, is_public, created_at
- `threads` / `comments`: 公開結果への投稿・返信（画像添付 URL 可）
- `likes`: スレッドへの♡
- 画像: Supabase Storage（avatars/, thread-images/）
